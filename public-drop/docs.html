How a wallet is made

Each wallet is one random 32-byte value, made in your browser. There is no seed phrase, no master key and no key derivation tree: every wallet is independent.

  1. The browser's secure random generator (crypto.getRandomValues) gives 32 random bytes.
  2. Those bytes are hashed with SHA-256 together with a pool of mouse-movement samples and a counter: sha256(random ‖ pool ‖ counter). The mouse samples can only add randomness, never remove it, because the browser's random bytes are always part of the input.
  3. The 32-byte result is an Ed25519 seed. The public key is derived from it with the standard Ed25519 algorithm (the @noble/curves library).
  4. The wallet address is the public key written in base58, which is how Solana shows addresses.
  5. The private key you can copy is the 64 bytes seed ‖ public key in base58. This is the format Phantom, Solflare and Backpack accept under “Import private key”. “Copy as keypair.json” gives the same 64 bytes as a list of numbers, for the Solana command line.

The backup file

The file is plain JSON. With no passphrase it looks like this (shortened):

{
  "format": "keypool-1",
  "created": "2026-11-01T12:00:00.000Z",
  "note": "Random keys, no seed phrase. This file is the only backup. Keep copies.",
  "keys": [ { "type": "sol", "address": "...", "secret": "..." } ]
}

When you open a file, Keypool re-derives every address from its secret and refuses the file if any address does not match.

With a passphrase

The passphrase is turned into a key with scrypt (N=65536, r=8, p=1, a random 16-byte salt), then the whole file is encrypted with AES-256-GCM through the browser's WebCrypto, with a random 12-byte nonce. The file format name is authenticated, so a changed file fails to open. The result is a file with the format keypool-1-encrypted.

If you forget the passphrase, nobody can open the file, including us. We never see it.

One wallet per file

“Save only this wallet” writes a file with just that wallet. A leaked file then exposes one wallet, not all of them. Your full backup file is still worth keeping.

What leaves your browser

Nothing is meant to. Keys are made and kept in the page. There is no account, no server that receives keys, no analytics and no third-party scripts. Fonts and the script are served from the same site.

This is enforced by the page's Content Security Policy, which the browser applies:

default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:;
font-src 'self'; connect-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'

connect-src 'none' means the page is not allowed to make any network request (no fetch, no XHR, no WebSocket). The one exception you control is the “View on Solscan” link: if you click it, a new tab opens Solscan and that site learns the address.

Check it yourself

  1. Watch the network. Open your browser's developer tools, go to the Network tab, reload, make some wallets. You should see only this site's own files (the page, its stylesheet, its script and fonts), and nothing after you press “Make wallets”.
  2. Try to break the policy. In the Console tab, run fetch('https://example.com'). The browser should refuse it with a Content Security Policy error.
  3. Read the policy. In the Network tab, click the page and look at the response headers for content-security-policy. Or run curl -I https://keypool.fun.
  4. Go offline. Save this site's page, disconnect from the internet, and open it from your own disk. Make a wallet. Everything still works, because nothing needed a server.
  5. Read the code. The source is public at github.com/HastyBu1lds/keypool. Key generation and the file format are in src/core.js, and the page's logic is in src-drop/app.js. The script this site serves is a minified bundle built from those files with npm run build.
  6. Check an address. Show a wallet's private key, paste it into any other wallet app (Phantom, Solflare) or into the “Check a private key” box, and confirm the same address comes out.

Tests

The key code has automated tests. They check the Ed25519 code against the official RFC 8032 test vector, check that 25 generated keys are all different and can be re-imported, and check the file format both plain and encrypted, including that tampered files and wrong passphrases are rejected.

What the fees are for

The creator fees earned from trading $KEYPOOL are meant to pay for hosting keypool.fun: the domain and the servers that deliver this page. Nothing more is promised. There are no returns, no buybacks and no rewards.

What the token is not

  • It is not needed to use Keypool. The wallet maker is free and works the same whether or not you hold the token. Nothing in the page checks for it.
  • It is not an investment and this is not advice. Tokens can lose all of their value. Never spend money you cannot afford to lose, and do not buy because of anything on this page.
  • We will never ask for your private keys, your passphrase or your backup file. Nobody from Keypool will message you first to ask for them. If someone does, it is a scam.

Limits and risks

  • Not audited. No independent security review has been done. Try a small amount first, send it out again, and only then use more.
  • No recovery. Lose every copy of your backup file (and any passphrase) and the coins are gone. Nobody can reset it. Make a new backup after adding wallets.
  • The file is the thing to guard. A backup file holds copies of your keys. Lock it with a passphrase, keep copies private, or save wallets one at a time.
  • Your device is the weak point. Malware, a hostile browser extension or someone looking at your screen can read keys in any wallet, including this one. Keypool cannot protect a compromised computer.
  • Printing leaves copies. Printing paper wallets puts private keys on paper and in the printer's queue.
  • Solana only, and the file format is Keypool's own. It is not Bitcoin's wallet.dat.
  • No seed phrase is a trade-off, not magic. You gain independent keys and no master phrase. You give up the ability to rebuild everything from words.
